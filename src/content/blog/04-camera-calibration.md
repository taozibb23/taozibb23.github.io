## 一、标定到底在解决什么问题

标定,顾名思义,听起来是很高级的东西。在这篇文章里,标定是给相机做的一次"测试"——求解相机和外界物理世界的关系。

我们的相机不知道外界的物理世界,我们甚至不知道小孔成像和现实画面与相机内部的投影到底是什么关系。标定就是来解决这个问题的:通过标定,可以知道外界拍摄的物理世界和相机内部投影之间的具体参数关系。有了这个关系,才能把外部的物理量转化到相机内部、再到程序里。

所以,凡是用相机做感知的方向,标定永远是第一课。对下一步的 PnP 测距来说,如果不知道标定出来的内参,我们根本不知道像素怎么换算成物理的毫米大小。(顺带说一句:PnP 还需要解算出外参。)

标定之后可以得到 **9 个参数**:**4 个内参**(后面可以写成一个内参矩阵)+ **5 个畸变系数**。一切相机感知与外界的交互,都需要先标定得知这些参数。

如果你不去测试,就像你有了狙击枪,开枪前从来不调整瞄准镜,直接用网上的参考值。那你得出的数据永远是模糊的,打目标也是偏的,因为瞄准镜本身就是歪的。不标定,大部分和相机有关的应用都做不了。

## 二、内参在说什么

我们初中就知道小孔成像的大概原理,内参就是根据这个来求解外界物理比例和相机内投影的关系:

```
u = fx · X/Z + cx
v = fy · Y/Z + cy
```

- **fx、fy 是焦距**,这里的单位是**像素**。这个单位一开始有点蒙,没关系,后面会说。
  我实测的值是 **500.82 / 502.92**。
- **cx、cy 是主点**。主点是什么?就是主光轴直接打在画面上的位置,也就是中心,所以叫 c center。
  我实测的值是 **345.46 / 246.65**,和 640×480 的一半差不多。
- **X、Y、Z 是真实世界的坐标**,单位是米。
- **u、v 是相机里面的像素坐标**。

闭上眼睛,我大概讲一下这个公式是怎么来的。把成像的物体看成一个线段,我们只研究它的一个端点:点通过小孔在相机内成像,利用对顶角相等,可以根据相似三角形求出前面那个式子,也就是:

```
u = fx · X/Z      v = fy · Y/Z
```

再转化一下,变成更明显的相似形式:

```
u / fx = X / Z        v / fy = Y / Z
```

可以看出,**左边都是相机投影里的量,右边都是现实世界里的量**,这样就很好理解了。

Z 是物体到小孔的距离。先控制其他变量,可以看出 **Z 越大,比值越小**,所以越远的物体在相机内部成像就越小——现实里也是越远越小。

那 fx 的单位为什么是像素?它是这样来的:

```
fx = 物理焦距 ÷ 单个像素的物理尺寸
```

标定之后还可以反推出"一个像素等于多少毫米"。更直观的说法是:**如果我们知道装甲板的真实长宽,就可以算出画面里 1 个像素对应现实中的多少毫米。**

## 三、畸变系数

**k1、k2、k3 是径向畸变**,我实测的值是:

```
0.098268 / −0.290968 / −0.0018205
```

**p1、p2 是切向畸变**,我实测的值是:

```
−0.0039597 / 0.225666
```

- **径向**就是镜头的画面鼓起来或者凹下去了,分为**桶形**和**枕形**两种。
- **切向**是镜头或者其他部件**装配没装正**造成的。

一条直线在照片的边上会变弯,这是因为成像透镜本身的物理性质——畸变避免不了,但可以用已知的固定公式把它化解掉。

## 四、标定流程

```
1. 打印棋盘格     → 我的是 10×7 内角点,格子边长 15mm
2. 拍 15~25 张    → 一定要不同角度、不同位置、不同方向,最好覆盖画面的各个区域
3. 找角点         → OpenCV 封装了两个方法,这里有一个坑(见第九节)
4. 调用 calibrateCamera → 求解出 9 个数字
5. 验收           → 看重投影误差,再观察去畸变前后的图片对比
```

**流程里有两个"为什么",我一开始也没搞懂,后来才想明白:**

**为什么至少要 3 张?**

标定一共要解 **9 个未知数**。一张棋盘格照片能给我 70 个角点,看着很多——但它们**全都在同一个平面上**,只能约束"平面内"的关系,约束不了深度方向的东西。**每换一个姿态,就等于多了一组新方程。** OpenCV 在数学上要求至少 **3 个不同的姿态**才能解出来。

所以关键不是"拍得多",而是"**姿态不一样**"——同一个角度拍 20 张,信息量和拍 1 张差不多。

**为什么要求覆盖画面?**

因为相机的畸变**在画面边缘最明显,中心几乎没有**。如果只在中间拍,边缘的畸变系数就一点真实数据都没有,只能靠模型**往外推**——推出来的系数在边缘大概率是错的。所以要**让棋盘格出现在画面的每一个区域,四个角也要拍到**。

**顺便说一下重投影误差是什么**:把标定算出来的参数,重新把棋盘格的三维点投影回画面,再看投影点和实际检测到的角点差多少像素。**这个差值就是重投影误差**——它是标定质量的直接成绩单。

## 五、第一批:手拿着纸就拍 → 2.9615 像素

第一次测试,我是**手直接拿着纸**就开始标定的。

当时窗外有光线,我手拿着打印出来的棋盘格 A4 纸,对着摄像头拍。结果是:**重投影误差 2.9615 像素**,`cx = 379.0`。

差了有点多——我的画面宽 640,中心是 320,**cx 偏离了 59 个像素**。

第一次看到 2.96 的时候,我还不知道这个数据已经差很大了,以为还可以。我猜偏离的原因可能是相机自己装配的时候出了问题,另外我看拍出来的图片软软的、有弯曲,还有反光、有些模糊——**标定的照片质量本身就差**。

![第一批标定照片:手拿着纸,弯曲、反光、模糊](/images/blog/04-batch1-bad.jpg)

## 六、重点:怎么判断是「数据问题」还是「模型问题」

知道数据很差之后,我就开始诊断:**到底是数据的问题,还是相机模型代码的问题?**

OpenCV 有一个开关可以控制变量:**`CALIB_FIX_PRINCIPAL_POINT`**。

前面说了 cx、cy 是主点。为什么要固定主点呢?回想一下相似求解模型:相似模型是按比例算的,而相机投影的**原点**(坐标系基准点)就是主点。所以我们怀疑,会不会是主点出了问题?

但是**固定了主点之后,误差没有变化**。那就说明:**不是参数求解代码的问题,而是我们喂进去的棋盘格数据有问题。**

其实拍完之后,自己看一眼照片就能看出原因:手拿着纸造成弯曲、对着窗户反光太强、没把边缘的角点也拍进去导致数据不完整,等等。

**这里用到的就是控制变量法**:把主点固定住,如果误差幅度变小了,就有可能是主点偏移造成的;没变,就排除掉这条路。

这个思路在其他地方排查 bug 也一样能用——**怀疑哪个因素,就先把它固定住,看结果变不变**。

## 七、第二批:贴到英语书上 → 1.1362 像素

后面我拿了自己的**英语书**来改进:把棋盘格贴在上面,这样就满足了**共面、不弯曲**。重新拍摄之后,重投影误差降到 **1.1362**,好了很多,`cx` 也变成 **321.60**,基本就在中心。

但感觉误差还是偏大。于是我去观察数据,**统计棋盘格在画面里出现的位置**,发现:

> x 全部落在 **227 ~ 631** 之间,**左边从来没有出现过**。

也就是说,**左边约 1/3 的画面,一张都没拍到**——数据完整性不够。

为什么边缘这么重要?因为相机的畸变(透镜本身的性质)**主要发生在边缘处**。边缘的数据少了,畸变系数就算不准,边缘的重投影误差自然就大了。

![第二批标定照片:贴在英语书上,但只出现在画面右侧](/images/blog/04-batch2-mid.jpg)

## 八、第三批:补满覆盖 + 剔掉坏图 → 0.4827 像素

改进动作有两个。

**第一,补覆盖。** 我写了一个程序,在屏幕上把画面划成 **3×3** 的格子,拍到哪一格就记录哪一格,**要求 9 个格子全部满足**才算拍完。

补完之后,棋盘格的 x 覆盖范围从 `227~631` 变成了 **47~603**,左边终于补上了。

**第二,剔掉坏图。** 输出的时候,我发现有一张图片的角点明显不对,单张重投影误差高达 **1.29 像素**——模型只能靠已知的 15mm 格子尺寸硬倒推,再和检测到的点算误差,所以那张特别大。把它剔掉之后,误差从 **0.5575** 进一步降到 **0.4827 像素**。

最终标定结果:

| 参数 | 值 |
|---|---|
| fx / fy | **500.8168 / 502.9215** |
| cx / cy | **345.4589 / 246.6515** |
| k1 / k2 / k3 | 0.098268 / −0.290968 / −0.0018205 |
| p1 / p2 | −0.0039597 / 0.225666 |
| **重投影误差** | **0.4827184 像素** |

三批对比:

| 批次 | 张数 | 重投影误差 | 问题 → 改动 |
|---|---|---|---|
| 一(手拿纸) | 25 | **2.9615** | 纸弯了 → 贴到硬板上 |
| 二(贴硬板) | 20 | **1.1362** | 左边 1/3 没拍到 → 补满 9 格覆盖 |
| 三(补覆盖 + 剔坏图) | 19 | **0.4827** | 剔掉 1 张坏图 |

**误差降到了原来的 1/6。**

![去畸变前后对比:边缘的直线被拉直了](/images/blog/04-undistort-compare.jpg)

补覆盖和剔坏图这两步,**作用是不一样的**:

- **补覆盖**解决的是"**边缘没有真实数据**"的问题。畸变是**系统性**的,边缘一整圈都受影响;数据不全,整圈都只能靠外推。
- **剔坏图**解决的是"**个别点把结果拉歪**"的问题。一张坏图的误差特别大,在最小二乘里**平方之后权重更高**,一颗老鼠屎就能影响全部参数。

一个是"**把该有的数据补齐**",一个是"**把不该有的数据拿掉**"——方向刚好相反。

## 九、我判断错的两次

### 第一次:经典检测器一个都没命中

一开始我用的是 OpenCV **经典版本**的 `findChessboardCorners`——**0/25 命中**。当时一个都识别不到,吓死我了。

后面换成了 **`findChessboardCornersSB`**,命中 **22/25**。当时没识别到的那几张,就是我前面说的坏图。

**最离谱的是**:把棋盘格的参数从 **10×7 写成 7×5**,它居然也能识别"成功"——实际上是错误的。我当时是看了一下代码,再把我电子版 PDF 棋盘格和程序找到的角点数量对比,才发现不对。

所以后来我明白了一件事:**报错不可怕,可怕的是它说成功了。**

这里还有个反直觉的发现。我一开始以为 SB 版一定比经典版强,但后来在**第三批那批清晰、贴板的图**上试了一下:

| 检测器 | 第一批(糊/反光/弯) | 第三批(清晰/贴板) |
|---|---|---|
| 经典 `findChessboardCorners` | **0/25** | **19/19** |
| `findChessboardCornersSB` | **22/25** | 14/19 |

**SB 并不是"永远更好"**:它在**烂图**上很强,但在**好图**上反而不如经典版。

所以我的代码里最终是**两个都用、按顺序重试**:先普通 SB,不行再 SB 的 exhaustive 模式,还不行再上经典版 + 亚像素优化。**哪张图用哪种方法不重要,能把角点稳稳找出来才重要。**

### 第二次:清晰度判断算错了区域

一开始我判断"这张图清不清晰",用的是**整张图片**的拉普拉斯方差。

但问题是:**背景一干净、或者背景在画面里占比很小的时候,整张图的分数就会很低**,于是明明很多图片很清楚,却被判成模糊;反过来背景很乱的时候,又会被误判。

正确做法是:**只算棋盘格所在的那块区域**。

这让我意识到,标定对图片的要求不只是"棋盘格本身清晰、角度合适",**背景也要干净,或者干脆不要背景**。

## 十、标定精度怎么换算成毫米

公式是:

```
1 个像素 ≈ Z / fx
```

Z 是物理距离。其实我觉得,用已知尺寸的装甲板来反推一个像素有多大,会更好理解。

我的重投影误差是 **0.4827 像素**。但光说这个数不清晰,换算一下:

```
1 米处:1 像素 ≈ 1.996 mm
0.4827 像素 × 1.996 mm/像素 ≈ 1 米处 0.96 mm
```

**也就是说,在 1 米的地方,定位精度大约是 1mm。** 这样的数据才有现实的冲击力,你们才听得懂。

距离变成 2 米的时候,一个像素对应的物理尺寸翻倍,误差也变成两倍——**所以测距越远,精度越差**。

## 十一、总结:我踩到的坑

1. **手拿着纸标定** → 纸会弯,不满足"角点共面"
2. **边缘没有拍进去** → 边缘的畸变只能用程序往外推,而不是真实数据
3. **经典版检测器一个都没命中** → 换成 SB 版
4. **最危险的是:错误的棋盘格尺寸也能"成功"运行** → 静默失败比报错可怕得多
5. **清晰度判断算错了区域** → 不该算整张图,应该只算棋盘格区域
