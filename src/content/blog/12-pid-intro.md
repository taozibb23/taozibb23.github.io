## 初识PID

### 一、引入：洗澡水温的例子

当你在晚上洗澡的时候是不是时常被热水器的冷热控制感到苦恼，拧一点又太热往回拧一点又太冷了，每次都要一会儿的调试温度才能到合适的温度洗澡。

那么这个调试温度的过程就是 **P I D**——**Proportion（比例）、Integral（积分）、Derivative（微分）**。

你打开水阀，感觉水太冷了跟冰水一样，这时候你会往热水的方向拧很多；如果感觉水只是温温的，你就会拧一点点到热一点点的水温。

**拧的幅度大小就是 P 比例。**

---

### 二、比例控制（P）

在上一个介绍 P 的比例的时候，如果你是一个对温度很敏感精确的人，在多次调试你按照 P 比例的这种说法来调节温度的话，除非你是可以往理想温度调试无数次，当然在这种情况下也只能无限接近但是不可能准确的。

那么现在就引入 **I 积分**。

---

### 三、积分控制（I）

我不用纯数学的角度解释 I。I 就是你距离目标温度第一次差一些记录下来，最后按照一定的比例相乘然后加上 P 的比例合成一个力度去推动，这样每次的差一点点都会被 I 这个选项给补上。运用这两个参数就可以更快的贴近目标的温度。

就像我们上初中的显微镜操作，有粗准焦螺旋和细准焦螺旋：

- **粗准焦螺旋像是 P**
- **细准焦螺旋像是 I**

粗准焦螺旋每一次都调节的过大导致每次都差一些或者超过，所以粗准焦螺旋调节完成之后就使用细准焦螺旋。

而 **D** 就是防止这两个参数加起来的时候调节把水调节的过热。

---

### 四、微分控制（D）

D 就是防止超调的。D 就是等于一个参数乘以上一个误差值来得到每走一步的时候就往后挪一点，如果这两步的差值大那么说明在快速接近水温，很有可能调节的时候超过水温，所以差值就可以体现实际情况。

这个动态的过程很神奇，在这个基础上我的另外一个 blog Kalman Filter 里面的 K 也很神奇，动态的权衡几种因素或者说因子，把这种动态反映的数值整合了起来。

---

### 五、引入鼠标控制

这个例子作为一个引入，下面我再举出一个例子带入具体的数值和实际情况（这个也同步在我的 GitHub 主页上面）。比较简单的运用，对于 FPS 游戏的"锁头外挂"这种的定位，需要通过图像映射到程序里面变成 Mat 矩阵来进行判断（当然这只是传统的 CV 方式）。

说多了，下面我就用控制鼠标移动到目标位置也就是锁头这种说法来再次说明 PID。

> **请正确运用技术，仅仅是学习交流内容，若出现滥用开发游戏外挂和违规行为作者概不负责。**
> 

对于一个目标你获取到它的位置之后，你又知道自己光标的位置，这时候就有两个坐标。对于两个确定的坐标，算出距离或者是 XY 的差值 error（实际的时候只需要算一个，另外一个封装好就行，听不懂没关系也可以两个都列式子计算分别作出结果然后移动就是了）。

回到例子里，这个鼠标的例子和上面水温的例子对比，鼠标的坐标是一个比温度感知更精确的数值。你可以认为你的屏幕是 1920×1080，长的 X 最长是 1920，Y 的长度是 1080 的一个坐标。

当然如果你想要那种暴力锁头外挂一帧之间瞬移过去的那我没得说，你直接做差移动就好。这里只是作为一个例子让鼠标的移动更加丝滑不卡顿，更像真人操作。并且对于真实的应用场景，不论是和物理世界的交互还是实验数据出现的毛刺，都不可能像两个坐标做差移动那么简单。

### 六、公式介绍

#### 1. P_output = Kp × error

前面热水调节提到的 P 对应比例，那么 y = kx，k 就是作为比例，这从数学上很容易理解——k 越大要调节的幅度越大，k 越小要调节的幅度越小。

当然只用 P 会存在一个问题：因为 k 是比例，对于比例取值的 error 是永远到不了那个实际值的，只会无限接近。

#### 2. I_output = Ki × integral

（积分也就是累加一个东西的意思，可以暂且看成一个符号也行）

integral = integral + error

积分等于上一次调节的积分加上误差。一个参数是等于上一时刻它的值加上误差，这就实现了误差 error 的累加也就是积分，也是动态变化的，很神奇。放在程序里就可以根据实际情况自动调节，Ki 也是决定对于积分值要取多少比例的。

积分可以把 P 存在的小小误差弥补，但是因为累加的原因就算有 Ki 的比例调节也容易调节过度——过冲。

#### 3. D_output = Kd × (error - prev_error)

微分的作用是根据动态的情况来刹车，也弥补了 I 过冲的问题。但是容易受到噪声的影响，因为噪声的起伏很大，可能出现 error = 1000, prev_error = -1000 这种起伏的毛刺（我的解决方法就是先对目标进行 Kalman 再对鼠标控制的时候用 PID，这个不重要）。

error 和 prev_error 也反应出实际的距离差距，判断是否超过目标，超过的话 D 就为负数，没超过就类似和 I 一样的参数起到细准焦螺旋的作用。

#### 4. 为什么每一个值都要乘参数？

我个人认为一个是好调节，另外一个是丝滑的作用。PID 就是一个慢慢接近的平滑丝滑处理，想想你在高速变道超车，总不可以一下打死，肯定是慢慢来的嘛。

结合以上的部分的话得出了：

output = P + I + D

把 3 个条件参考加入进来，就得到了最后移动的结果。

### 七、手算例子

#### 例子1：纯 P 控制

比如 target = 1000，现在我们鼠标在 0，kp = 0.3，ki = 0，kd = 0。

误差 = 1000 - 0 = 1000

P输出 = 0.3 × 1000 = 300

鼠标移动到 0 + 300 = 300

误差 = 1000 - 300 = 700

P输出 = 0.3 × 700 = 210

鼠标到 300 + 210 = 510

误差 = 1000 - 510 = 490

P输出 = 0.3 × 490 = 147

鼠标到 510 + 147 = 657

误差 = 1000 - 657 = 343

P输出 = 0.3 × 343 = 102.9

鼠标到 657 + 102.9 = 759.9

继续算下去你会发现，它越来越接近目标，但永远也到不了 1000——这就是 静差。所以我们需要引入 I。

#### 例子2：加入 I（积分）

直接在纯 P 的例子上加入 Ki，假设 Ki = 0.01。我们从达到静差的时候开始加入 I 进行计算，假设鼠标稳定在 998，integral = 0，error = 2。

第1步：

error = 1000 - 998 = 2

integral = 0 + 2 = 2

P_output = 0.3 × 2 = 0.6

I_output = 0.01 × 2 = 0.02

total_output = 0.6 + 0.02 = 0.62

鼠标移动到 998 + 0.62 = 998.62

第2步：

error = 1000 - 998.62 = 1.38

integral = 2 + 1.38 = 3.38

P_output = 0.3 × 1.38 = 0.414

I_output = 0.01 × 3.38 = 0.0338

total_output = 0.414 + 0.0338 = 0.4478

鼠标到 998.62 + 0.4478 = 999.0678

第3步：

error = 1000 - 999.0678 = 0.9322

integral = 3.38 + 0.9322 = 4.3122

P_output = 0.3 × 0.9322 = 0.2797

I_output = 0.01 × 4.3122 = 0.0431

total_output = 0.2797 + 0.0431 = 0.3228

鼠标到 999.0678 + 0.3228 = 999.3906

根据上面的结果看，积分那个项一直在累计，值慢慢推进到目标值。对于数据需要你们自己看数据进行感受，我就少一些讲解。

如果继续下去，I 不断累积很容易超调，会超过 1000，因为 I 不会清零会一直加一点点。

#### 例子3：加入 D（微分）

D 是 Kd × (error - prev_error)。越接近就会拉回一点点防止超调，如果远离了目标会帮助其他数值拉近一点点。当然这个是为了和前面的两个数值抗衡的，不能太大，所以数值都会比较小。

假设 Kd = 0.1。P 和 I 都是靠近往前没有减法只有加法，终究会超调，所以要加入 D 达到动态平衡的效果。

先看没有 D，只有 P 和 I 的时候的第 4 步：

error = 1000 - 999.3906 = 0.6094

integral = 4.3122 + 0.6094 = 4.9216

P = 0.3 × 0.6094 = 0.1828

I = 0.01 × 4.9216 = 0.0492

output = 0.1828 + 0.0492 = 0.2320

鼠标移动到 999.3906 + 0.2320 = 999.6226

现在已经越来越接近了，但是按照这个趋势，I 会累加，就算累加的很少，一直按照前面的加的大小 0.04 也最终会有超调的时候，数字无限多的时候会超过。

如果第 4 步的计算加入 D：

current error = 0.6094

prev_error = 0.9322

derivative = 0.6094 - 0.9322 = -0.3228

D = 0.1 × (-0.3228) = -0.0323

P 和 I 还是和之前一样：

P = 0.3 × 0.6094 = 0.1828

I = 0.01 × (4.3122 + 0.6094) = 0.0492

total_output = 0.1828 + 0.0492 - 0.0323 = 0.1997

鼠标移动到 999.3906 + 0.1997 = 999.5903

可以看到加入 D 之后就开始轻微的刹车了，少了一丢丢。因为已经很靠近了，所以就温和的刹车；如果是距离很远的话，就会急刹车。

### 八、更明显的对比：从较远距离开始

为了更加明显的看到三者的关系和作用，假设鼠标在 800，目标 1000，误差 200。此时积分可能还不大（假设 integral=0），Kp=0.3，Ki=0.01，Kd=0.1。

第1步：

error = 200

integral = 0 + 200 = 200

P = 0.3 × 200 = 60

I = 0.01 × 200 = 2

D = 0（因为上一帧误差还没定义）

output = 60 + 2 + 0 = 62

鼠标移动到 800 + 62 = 862

第2步：

error = 1000 - 862 = 138

prev_error = 200

integral = 200 + 138 = 338

P = 0.3 × 138 = 41.4

I = 0.01 × 338 = 3.38

D = 0.1 × (138 - 200) = 0.1 × (-62) = -6.2

（这里 D 开始起作用了，往后缓缓的稳了一点点）

output = 41.4 + 3.38 - 6.2 = 38.58

鼠标移动到 862 + 38.58 = 900.58

第3步：

error = 1000 - 900.58 = 99.42（约等于 99.4）

prev_error = 138

integral = 338 + 99.4 = 437.4

P = 0.3 × 99.4 = 29.82

I = 0.01 × 437.4 = 4.37

D = 0.1 × (99.4 - 138) = 0.1 × (-38.6) = -3.86

output = 29.82 + 4.37 - 3.86 = 30.33

鼠标移动到 900.58 + 30.33 = 930.91

数值的变化放在程序里面运行的时候，加入一个循环就变成了动态的数字进行调节。数学的思想融入计算机算法，生活里面很多奇怪的想法都可以融入算法里面，达到一定的效果
